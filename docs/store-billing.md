# Стора-биллинг: Apple IAP / Google Play Billing vs Lemon Squeezy

Решение (2026-05): **продаём подписку ТОЛЬКО на вебе (govori.io → Lemon Squeezy). Приложения — чистые клиенты: ввод лицензионного ключа, никаких покупок внутри.** Это легально обходит и Apple IAP, и Play Billing (0% комиссии сторам), и не требует менять то что уже построено.

## Почему так можно

- **Apple** требует IAP для цифровых подписок, ПОТРЕБляемых в приложении. Но «reader / multiplatform» исключение (Guideline 3.1.3): приложение может разблокировать сервис, купленный в другом месте, БЕЗ IAP — если внутри не продаёт и не «стирит» к покупке. Плюс с 2025 (Epic v Apple, US) и DMA (EU) разрешены внешние ссылки на оплату без комиссии — это запасной путь.
- **Google Play** — аналогично: подписку, купленную вне приложения (на вебе), приложение может просто потреблять; есть и User Choice Billing. Главное — не встраивать покупку/стиринг внутрь.

## Жёсткие правила для приложений (чтобы пройти ревью)

- ❌ НЕ добавлять в приложение кнопку «Оформить подписку» / «Купить» / цены.
- ❌ НЕ давать ссылку на govori.io/checkout из приложения (особенно Apple — не «стирить»).
- ✅ Только нейтральный ввод: «Введите ключ доступа» (как сейчас в GovoriApp / OnboardingScreen).
- ✅ Лендинг + checkout + выдача ключа — всё на вебе, вне приложений.

## Что это значит для текущего кода

Ничего менять не надо — оба клиента (iOS/Android) уже устроены как «ввод ключа, без IAP». Достаточно НЕ добавлять покупку в приложения и держать формулировку онбординга нейтральной (без упоминания цены/где купить).

## Риск

Apple-ревью бывает придирчив, если очевидно что есть платный сервис без IAP. Митигация: нейтральные тексты, ноль покупочного UI. Если зарубят — включить external-purchase-link entitlement (US/EU, без комиссии) как fallback.
